# Платформа MAX: что умеет и где ограничения (под наш продукт)

Детали API, лимиты и примеры кода — в [`docs/max/GUIDE.md`](max/GUIDE.md) (снимок официальной документации от 2026-09-22). Здесь только карта возможностей, проверенные факты и открытые вопросы. Организационные ответы MAX на Q&A — в [CASE_BRIEF.md §9](CASE_BRIEF.md#9-что-уточнили-организаторы-qa-5-w1).

## 1. Форматы, которые допускает кейс

| Формат | Допустим | Комментарий |
|---|---|---|
| Чат-бот | да | Диалог 1:1 и работа в групповых чатах (с ограничениями ниже) |
| Чат-бот + мини-приложение | да | Мини-приложение живёт только внутри бота: URL задаётся в настройках бота на business.max.ru, открывается кнопкой в чате с ботом, кнопкой `open_app` или диплинком `?startapp=` ([GUIDE §10](max/GUIDE.md#10-мини-приложения-web-apps)) |
| Отдельный сайт или веб-приложение вне MAX | нет | «Основной пользовательский сценарий должен быть доступен для проверки в MAX» (PDF 7). Сайт может быть вспомогательным (лендинг с QR), но не средой сценария |
| Канал MAX | как дополнение | Бот-админ может публиковать посты и модерировать комментарии; для нашего сценария не нужен |

Бонус +0,15 дают за осмысленную связку «бот + мини-приложение» или полезные уведомления, при полностью работающем основном сценарии (CASE_BRIEF §8).

## 2. Возможности, на которые опирается продукт

| Нужно продукту | Есть в MAX | Как | Источник |
|---|---|---|---|
| Бот в домовом чате читает сообщения | да, с условием | Только если бот **администратор чата с правом `read_all_messages`**; иначе событие `message_created` из группы не приходит | [GUIDE §0 п.9, §6](max/GUIDE.md#6-чаты-участники-права) |
| Бота можно добавить в групповой чат | да, с условием | Настройка «Приватность» бота на business.max.ru, **по умолчанию запрещено**. Наш бот создан организаторами → проверить и при необходимости просить их включить | [GUIDE §0 п.10](max/GUIDE.md#0-главное-что-легко-упустить) |
| Ответить в чате кнопками, обновлять сообщение (счётчик «я тоже», статус) | да | `inline_keyboard`, `POST /answers` заменяет сообщение, `PUT /messages` редактирует; в группах без ограничения по сроку | [GUIDE §4–5](max/GUIDE.md#4-отправка-сообщений) |
| Написать пользователю лично после действия в группе | да, с условием | `POST /messages?user_id=` работает, если пользователь **запускал бота** (диалог существует); иначе 403. Значит, в сценарии нужен шаг «открыть бота» (кнопка/диплинк) | [GUIDE §2, §4](max/GUIDE.md#2-основы-api) |
| Уведомления о смене статуса заявки | да | Сообщения в ответ на действия пользователя или по его подписке. Массовые и рекламные рассылки запрещены правилами (п. 1.5 требований) | [GUIDE §12](max/GUIDE.md#12-правила-платформы-которые-влияют-на-код) |
| Привязать чат к дому, пользователя к квартире/роли | да, своими силами | `chat_id` из событий `bot_added` / `message_created`; **реестр чатов ведём сами** (`GET /chats` удалён). Роль и дом — наша БД | [GUIDE §6](max/GUIDE.md#6-чаты-участники-права) |
| Онбординг арендатора без Госуслуг | да | QR/диплинк `https://max.ru/t446_hakaton_max_bot?start=house_<id>` → событие `bot_started` с payload; `?startapp=` для мини-приложения | [GUIDE §9](max/GUIDE.md#9-диплинки) |
| Мини-приложение знает, из какого чата открыто | да | `WebApp.initDataUnsafe.chat.{id,type}` (`DIALOG`/`CHAT`/`CHANNEL`); доверять только после проверки `initData` на бэкенде (HMAC) | [GUIDE §10](max/GUIDE.md#10-мини-приложения-web-apps) |
| Авторизация в мини-приложении без логина/пароля | да | `initData` подписан токеном бота; бэкенд проверяет подпись и `auth_date` (окно ~1 ч), заводит сессию по `user.id` | [GUIDE §10](max/GUIDE.md#проверка-initdata-на-бэкенде-обязательно) |
| Фото проблемы от жителя | да | Входящие вложения `image` в `message.body.attachments[]` с `payload.url`; исходящие — через `POST /uploads` | [GUIDE §7](max/GUIDE.md#7-медиа-и-вложения) |
| Геолокация / контакт | да | Кнопки `request_geo_location`, `request_contact` (номер верифицируется HMAC) | [GUIDE §5](max/GUIDE.md#5-клавиатуры-и-callback-кнопки) |
| Поделиться результатом (например, обращением в ГЖИ) в чат | да | `WebApp.shareMaxContent({mid, chatType})` для сообщений бота; `downloadFile()` для PDF; диплинк `max.ru/:share` | [GUIDE §9–10](max/GUIDE.md#9-диплинки) |
| Закрепить сводку в чате, менять описание чата | да | `PUT /chats/{id}/pin`, `PATCH /chats/{id}` — боту-админу | [GUIDE §2](max/GUIDE.md#все-методы) |
| QR-сканер в мини-приложении | да | `WebApp.openCodeReader()` | [GUIDE §10](max/GUIDE.md#max-bridge) |
| Команды бота (`/start`, `/help`) | да | `PATCH /me/commands`, до 32; встроенных команд нет | [GUIDE §8](max/GUIDE.md#8-команды-бота) |

## 3. Чего в MAX нет (учитывать в дизайне и в слайде «ограничения»)

- Бот **не создаёт чаты и не добавляет участников** (метод добавления удаляется 30.09.2026). Сценарий «бот добавляет представителя УО в чат» невозможен; возможно: снять админа/участника, назначить админом того, кто уже в чате, закрепить контакты новой УО ([GUIDE §6](max/GUIDE.md#6-чаты-участники-права); Q&A 5).
- **Нет списка чатов бота** (`GET /chats` удалён): реестр домовых чатов ведём в своей БД. Это же снимает «ограничение 1000 чатов», о котором говорил эксперт.
- Бот не пишет первым тому, кто его не запускал.
- Нет опросов, реакций, тредов и платежей в Bot API (по снимку документации). Голосование делаем кнопками с редактированием сообщения.
- Цифровой ID (льготные статусы) — отдельный API для юрлиц, боту в хакатоне недоступен ([GUIDE §11](max/GUIDE.md#11-каналы-комментарии-цифровой-id)).
- Нельзя узнать, включены ли у пользователя уведомления ([faq/chatbots](max/reference/faq/chatbots.md)).
- Кнопки теряются при пересылке сообщения; в комментариях каналов не работают ссылки и упоминания.
- Ник бота не меняется; логотип, описание, приватность и URL мини-приложения — на business.max.ru **у организаторов**.

## 4. Технические требования и лимиты, влияющие на архитектуру

| Требование | Значение | Следствие для нас |
|---|---|---|
| Базовый URL | `https://platform-api2.max.ru`, заголовок `Authorization: <token>` без Bearer | Клиент API — один адаптер с этим заголовком |
| TLS | Сертификат Минцифры; Python без CA падает | В Docker-образе добавить `docs/max/certs/russiantrustedca.pem` в доверенные |
| Приём событий | **Только webhook** в проде: HTTPS, порт 443, доверенный сертификат, ответ 200 ≤ 30 с; без успешных ответов 8 ч подписка удаляется | Caddy с Let's Encrypt; endpoint отвечает сразу, обработка в фоне; переподписка при старте; healthcheck и watchdog на период проверки 30.09–14.10 |
| Секрет вебхука | заголовок `X-Max-Bot-Api-Secret` | Проверять, иначе 403 |
| Дубли событий | возможны | Идемпотентность по `update_type + timestamp + mid/callback_id` |
| Лимиты | 30 RPS на API; 2 сообщения/правки/ответа в секунду в один чат | Очередь исходящих (outbox) с лимитером на чат; retry на 429/5xx/`attachment.not.ready` |
| Long polling | 2 RPS, батч 100, TTL 24 ч; несовместим с активным вебхуком | Только локальная разработка; удалять подписку перед polling |
| Текст сообщения | ≤ 4000 символов, markdown/html | Рендер сообщений — отдельный слой шаблонов |
| Клавиатура | ≤ 210 кнопок, 30 рядов, 7 в ряду; текст кнопки ≤ 128 | — |
| Диплинк | `?start=` ≤ 128 символов; `?startapp=` ≤ 512, `[A-Za-z0-9_-]` | Короткие коды домов/заявок, без ПДн |
| Мини-приложение | HTTPS, URL ≤ 1024 символов, один открыт одновременно; `initData` проверять на сервере | Стабильный домен; URL отправить организаторам через форму заранее |
| Правила платформы | политика ПДн и сведения об операторе доступны пользователю; пользовательский контент — принятие условий и удаление по жалобе; защита от подмены запросов | Команда `/privacy`, экран условий в мини-приложении, проверка подписи и секрета |

## 5. Где показать сильный фронтенд

Мини-приложение — единственная поверхность MAX со свободным UI (React, любой CSS). Организаторы рекомендуют React и дают [MAX UI](https://dev.max.ru/ui) (React-компоненты в стилистике MAX, [github](https://github.com/max-messenger/max-ui), Figma-гайд) и [MAX Bridge](max/reference/platform/webapps/bridge.md) (платформа, тема устройства, кнопка «Назад», haptics, шеринг, QR). Сценарии, где мини-приложение оправдано по PDF 15 и совпадает с нашим продуктом: список и фильтры заявок по 50 домам (диспетчер УО), таймлайн заявки, сравнение сроков с нормативом, история дома. Чат остаётся для коротких действий: одна кнопка, подтверждение, уведомление.

## 6. Инструменты

- Python: официальные SDK только TS и Go; для Python — `maxapi` (сообщество, стиль aiogram, 1.2.x, работает с `platform-api2`, CA в комплекте) или свой тонкий клиент по [OpenAPI-схеме](max/openapi/schema.yaml) v0.0.33. Сравнение и рекомендация — в [DECISIONS.md](DECISIONS.md).
- Проверить актуальность перед сдачей: [changelog API](max/reference/api/changelog-api.md), [changelog платформы](max/reference/platform/changelog-platform.md); обновление снимка — команда в [`docs/max/README.md`](max/README.md).

## 7. Открытые вопросы к платформе (проверить руками в первый день)

1. Разрешено ли добавление `@t446_hakaton_max_bot` в групповые чаты (настройка приватности у организаторов). Если нет — писать организаторам сразу; запасной сценарий: диалог с ботом + диплинк/QR дома.
2. Приходит ли `message_created` из группы после назначения бота админом с `read_all_messages` (проверить на тестовом чате).
3. Открывается ли мини-приложение из группового чата кнопкой `open_app` и что приходит в `initDataUnsafe.chat` (документация говорит `CHAT`, проверить на iOS/Android/web).
4. Поведение мини-приложения в веб-версии MAX (десктоп): `shareContent`, `DeviceStorage`, `HapticFeedback` там недоступны, `downloadFile` и `shareMaxContent` — проверить.
5. Работает ли `notify=false` для тихих уведомлений в личке (для дайджестов).
6. Сроки: сколько дней организаторам нужно, чтобы прописать URL мини-приложения в настройках бота после отправки формы.

## 8. Проверено онлайн 22.09.2026 (дополнение к снимку)

Сверка с dev.max.ru, GitHub MAX и сторонними разборами (субагент, ссылки в скобках).

- **MAX UI**: пакет `@maxhub/max-ui`, стили `@maxhub/max-ui/dist/styles.css`, заявлен **React 18+**; совместимость с React 19 и Vite не подтверждена и не опровергнута — проверить в первый день, запасной вариант React 18. Компоненты: `Avatar`, `Button`, `IconButton`, `ToolButton`, `Cell*` (Action/Header/Input/List/Simple), `Counter`, `Dot`, `Panel`, `SearchInput`, `Spinner`, `Typography.*`, `Container`, `Flex`, `Grid`, `Input`, `Switch`, `Textarea`, `EllipsisText`, `Ripple`, `Profile`. Явно не найдены Tabs, Modal/Sheet, Badge, Snackbar, Skeleton, Segmented — смотреть Storybook https://max-messenger.github.io/max-ui. Автотема light/dark и платформа iOS/Android с оверрайдом пропсами. Figma-кит: `MAXUI-Figma.fig` в репозитории ([dev.max.ru/ui](https://dev.max.ru/ui), [github](https://github.com/max-messenger/max-ui)).
- **MAX Bridge**: в отличие от Telegram WebApp **нет** `ready()`, `expand()`, `close()`, `sendData()`, `MainButton`, `themeParams`/`colorScheme`, `CloudStorage`, попапов, платежей. Тему берём из MAX UI (автоопределение) или `prefers-color-scheme`; «главную кнопку» рисуем сами ([bridge](https://dev.max.ru/docs/webapps/bridge)).
- **Bot API**: нет платежей, опросов, реакций, тредов в группах, инвайт-ссылок, отложенной отправки; есть `notify:false` для тихих сообщений ([docs-api](https://dev.max.ru/docs-api), [сравнение с Telegram на vc.ru](https://vc.ru/telegram/2799410-sravnenie-max-bot-api-i-telegram-bot-api)). Комментарии есть только к постам каналов.
- **Пересылка сообщения боту** приходит как `message_created` с заполненным `link` — интерпретация схемы, не проверено на практике.
- **Срок редактирования сообщений**: сторонний разбор пишет «24 часа», официальный снимок ([GUIDE §4](max/GUIDE.md#4-отправка-сообщений)) — 7 суток в диалоге (без срока при `inline_keyboard`), без ограничений в группах. Верим официальному, проверим на тесте.
- **Модерация**: любое изменение настроек бота на business.max.ru (включая **привязку URL мини-приложения**) уходит на модерацию **до 48 рабочих часов** ([bots-create/create](https://dev.max.ru/docs/chatbots/bots-create/create)). Настройки у организаторов → отправить ссылку через форму не позже 25–26.09 и держать URL стабильным.
- **Регистрация своего бота** требует юрлицо, ИП или самозанятого-резидента РФ; для сдачи всё равно нужен бот организаторов, свой бот — только для отладки, если у кого-то в команде есть статус самозанятого.
- **Хостинг**: для входящих вебхуков достаточно Let's Encrypt; сертификат Минцифры нужен только для исходящих запросов к `platform-api2.max.ru`. IP-диапазоны MAX не публикуются → защита вебхука только секретом. VK Cloud даёт хостинг мини-приложений MAX с бонусом 2500 ₽/мес ([cloud.vk.com](https://cloud.vk.com/promopage/max-mini-app/), страница открывается не всегда). Timeweb Cloud и Selectel — быстрые VPS с доменом.
- **Python SDK**: `maxapi` 1.2.2 (15.08.2026), вебхуки через FastAPI/aiohttp/Litestar, FSM; форк `max-messenger/max-botapi-python` отмечен MAX как проверенный, но отстаёт от upstream.
- Отладка мини-приложения: в мобильном клиенте нет DevTools, тестируют через веб-версию MAX в браузере ([habr](https://habr.com/ru/articles/1039030/)).

## 9. Особенности `maxapi` 1.2.2 (проверено 23.09 на реальном токене)

- `bot.set_my_commands()` ходит в `PATCH /me`, MAX отвечает `404 method.not.found`. Использовать `bot.set_commands()` (`PATCH /me/commands`).
- `FastAPIMaxWebhook` разбирает событие внутри HTTP-запроса, а разбор (`process_update_webhook`) синхронно зовёт MAX API (`GET /chats/{id}`). Любая ошибка там превращается в 500 даже при `use_create_task=True` (проверено на fly 23.09). Поэтому у нас свой маршрут `api/webhooks/max.py`: секрет, 200 сразу, разбор и обработка в фоне.
- Хранилище состояния диалога подменяемое: `Dispatcher(storage=<класс BaseContext>)`; по умолчанию `MemoryContext`.
- Данные, которые middleware кладёт в `data`, приходят в хендлер аргументом с тем же именем (так передаётся `services`).
