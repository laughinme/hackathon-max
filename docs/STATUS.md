## Где мы

Фаза **Create**. Шаги 1–5 дорожной карты сделаны, из шага 6 — всё, кроме описания фото через LLM (ветка `feat/housing-dispatcher` поверх `feat/ticket-core`, [D-008](DECISIONS.md), [D-010](DECISIONS.md)). Житель выбирает дом (QR-диплинк или демо-дом), описывает проблему, получает заявку с нормативным сроком; диспетчер УО в чате или через REST видит очередь по сроку, меняет статус с комментарием; житель получает уведомление и подтверждает выполнение кнопкой. Демо-данные: 1 УО, 50 домов, 120 заявок.

**Стенд:** `https://domovoy.prooood.ru` — ВМ в Yandex Cloud (27.09, [D-009](DECISIONS.md)), автодеплой из `main` через GitHub Actions. Бот подписан на вебхук (подписка fly снята, машины fly остановлены), база и демо-данные подняты, `DATA-API.yaml` — 22/22 на стенде 27.09. Не проверено: живое сообщение от человека в MAX. Пока вебхук на стенде активен, локальный `polling` событий не получает.

Проверки: `cd backend && uv run pytest` (115 unit, 8 сценариев симулятора, 5 integration; `DATA-API.yaml` — 22/22 на стенде 27.09; +3 integration с `TEST_DATABASE_URL`), `PYTHONPATH=src uv run python -m scripts.simulate_flow` (8 сценариев), `ruff` и `pyright` чистые.

Классификатор переключается `CLASSIFIER=catboost|llm|rules`, сравнение — `scripts/compare_classifiers.py` (Q-18). Экран бота после текстового сообщения переезжает под него. В домовом чате: подсказка на жалобу, карточка заявки, «Я тоже», пульс, листовка с QR. Защита от повторных событий вебхука (`inbox`), `/privacy` с удалением данных.

Мини-приложение (шаг 4) отдаёт бэкенд по `/` того же домена. Открыто: **отправить `https://domovoy.prooood.ru/` в форму организаторов** (опоздали с 25.09, модерация до 48 раб. ч); uptime-монитор и бюджет в биллинге; набор жалоб от людей и прогон сравнения (Q-18); проверить групповой сценарий в живой группе; README для проверяющих и `DATA-API.yaml` готовы (24.09); замер сборки Docker ≤ 5 мин — повторить на стабильной сети (локально оборвалась загрузка catboost).

Параллельно: ML — синтетический датасет (`ml/dataset/`, train 1119 / test 350, обе метки) и обучение (`ml/training/train.py`) готовы, модели и `metrics.json` закоммичены в `ml/models/`; на test категория accuracy 0.94, аварийность accuracy/recall 0.966 (на синтетике того же генератора — оценка оптимистичная, см. Q-18). Дальше у ML: вычистить 5 почти-дублей train↔test; доля аварий в датасете искусственная (50% в каждой категории) — подобрать порог аварийности на правдоподобном распределении. Адаптер LLM-классификатора и скрипт сравнения уже есть (`CLASSIFIER=llm`, `scripts/compare_classifiers.py`). Сверка нормативных сроков с первоисточниками до 25.09 ([DATA.md §2](DATA.md)); кастдев 5–8 интервью.

**Проверить руками** (без этого шаги 3–4 под риском): добавляется ли бот в групповой чат и приходят ли сообщения после назначения админом с `read_all_messages`; открывается ли мини-приложение из группы. Если запрет — сразу письмо организаторам.

|---|---|---|
| Бота нельзя добавить в группы (настройка у организаторов) | снят 23.09 — организаторы разрешили | — |
| Организаторы не успеют прописать URL мини-приложения (модерация до 48 раб. ч) | средняя | отправить форму 25.09, стабильный домен, бот полноценно работает и без мини-приложения |
| Падение хостинга или подписки в период проверки 30.09–14.10 | средняя | restart policy, healthcheck, переподписка при старте, внешний uptime-монитор с уведомлением в MAX/Telegram |
| Ещё один контейнер (`ml/`, D-006) — доп. точка отказа на 30.09–14.10 | низкая | бэкенд откатывается на правила при недоступности `ml` (не роняет бота, только хуже классифицирует); `restart: unless-stopped` в compose, тот же uptime-монитор |
| Ошибки в нормативных сроках заметят эксперты ЖКХ | средняя | сверить справочник с первоисточниками до 25.09, указывать пункт документа, помечать спорное |
| Много команд сделают «бот заявок в УК» | высокая | отрыв за счёт SLA-движка, коллективных заявок, диспетчерской на 50 домов, эскалации, арендаторов |
| Перегруз фичами и сломанный основной сценарий | средняя | P0 сначала, freeze 27.09, прогон после каждого изменения |
