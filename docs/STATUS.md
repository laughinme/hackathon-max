## Где мы

Фаза **Create**. Шаги 1, 2 и 4 дорожной карты сделаны (ветка `feat/housing-dispatcher` поверх `feat/ticket-core`, [D-008](DECISIONS.md), [D-010](DECISIONS.md)). Житель выбирает дом (QR-диплинк или демо-дом), описывает проблему, получает заявку с нормативным сроком; диспетчер УО в чате или через REST видит очередь по сроку, меняет статус с комментарием; житель получает уведомление и подтверждает выполнение кнопкой. Демо-данные: 1 УО, 50 домов, 120 заявок.

**Тестовый деплой:** `https://domovoy-test.fly.dev` (fly.io, [D-009](DECISIONS.md)), бот подписан на вебхук, база и демо-данные подняты. Проверено: HTTPS, 403 без секрета, 200 и фоновая обработка с секретом, подписка на стороне MAX. Не проверено: живое сообщение от человека в MAX. Пока вебхук на fly активен, локальный `polling` событий не получает.

Проверки: `cd backend && uv run pytest` (70 unit; +3 integration с `TEST_DATABASE_URL`), `PYTHONPATH=src uv run python -m scripts.simulate_flow` (5 сценариев), `ruff` и `pyright` чистые.

Классификатор переключается `CLASSIFIER=catboost|llm|rules`, сравнение — `scripts/compare_classifiers.py` (Q-18). Экран бота после текстового сообщения переезжает под него; в группах бот пока молчит.

Мини-приложение (шаг 4) отдаёт бэкенд по `/` того же домена. Открыто: какой URL отправлять в форму организаторов — тестовый fly или будущий домен на Yandex Cloud; переезд на Yandex Cloud (D-009); набор жалоб от людей и прогон сравнения (Q-18); разрешение на группы от организаторов.

## Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Бота нельзя добавить в группы (настройка у организаторов) | **подтверждён 23.09** | письмо организаторам; пока ждём — шаг 4 (мини-приложение); запасной сценарий — диалог + QR дома |
| Организаторы не успеют прописать URL мини-приложения (модерация до 48 раб. ч) | средняя | отправить форму 25.09, стабильный домен, бот полноценно работает и без мини-приложения |
| Падение хостинга или подписки в период проверки 30.09–14.10 | средняя | restart policy, healthcheck, переподписка при старте, внешний uptime-монитор с уведомлением в MAX/Telegram |
| Ещё один контейнер (`ml/`, D-006) — доп. точка отказа на 30.09–14.10 | низкая | бэкенд откатывается на правила при недоступности `ml` (не роняет бота, только хуже классифицирует); `restart: unless-stopped` в compose, тот же uptime-монитор |
| Ошибки в нормативных сроках заметят эксперты ЖКХ | средняя | сверить справочник с первоисточниками до 25.09, указывать пункт документа, помечать спорное |
| Много команд сделают «бот заявок в УК» | высокая | отрыв за счёт SLA-движка, коллективных заявок, диспетчерской на 50 домов, эскалации, арендаторов |
| Перегруз фичами и сломанный основной сценарий | средняя | P0 сначала, freeze 27.09, прогон после каждого изменения |
| Код выглядит «сгенерированным» | низкая | архитектура соразмерна MVP, ADR в DECISIONS, честная пометка, где помогал ИИ |
