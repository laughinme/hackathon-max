Обновлено: 2026-09-22 (вт). Дедлайн сдачи: **30.09.2026 12:00 МСК** (8 дней). Полная хронология — [CASE_BRIEF.md §6](CASE_BRIEF.md#6-сроки-qa-1-w1).

## Где мы

Фаза **Dive → Create**. Кейс, вебинары, Q&A, документация MAX изучены; рынок и платформа проверены онлайн; предложены продукт, архитектура и план. Бот `@t446_hakaton_max_bot` отвечает на `GET /me`, вебхук не подписан.

**Код:** в `main` смержен прототип бота на `maxapi` (личный диалог, long polling, in-memory) и разложен по слоям `backend/src/{app,bot,domain,application,infrastructure}`; `cd backend && uv sync && PYTHONPATH=src uv run python -m scripts.simulate_flow` проходит 4 сценария. Ревью и список расхождений — [PROTOTYPE_REVIEW.md](PROTOTYPE_REVIEW.md). ML-каркас LoRA в `ml/` удалён; классификация жалоб — CatBoost на категорию и аварийность (оба — вход нормативного SLA-расчёта), LLM через API только для фото-описания и fallback-уточнения (D-005 в [DECISIONS.md](DECISIONS.md)). Классификатор вынесен отдельным сервисом `ml/` (свой контейнер, порт 8100, HTTP-контракт `/classify` в [CONTRACTS.md §4](CONTRACTS.md)) — бэкенд ходит туда через `infrastructure/ml/http_classifier.py` и откатывается на правила при недоступности (D-006). Моделей пока нет — обе части работают на заглушке-на-правилах уже сейчас, подключение готовых `.cbm` не требует правок кода.

Готово 22.09: `docs/` (кейс, платформа, рынок, продукт, архитектура, данные, контракты, решения), `case/README.md`, `.gitignore`, брифинг-страница для команды: https://claude.ai/artifact/T7CU7dR1LcdhpwNwqLKvbv (приватная, расшарить команде).

## Ближайшие шаги (22–23.09)

1. Команда принимает решения Q-01…Q-16 из [DECISIONS.md](DECISIONS.md) (созвон 30 минут).
2. **Проверить руками**: добавляется ли бот в групповой чат; приходят ли сообщения после назначения админом с `read_all_messages`; открывается ли мини-приложение из группы. Если запрет — сразу письмо организаторам.
3. Купить VPS и домен, поднять Caddy, поставить echo-вебхук (`POST /subscriptions`), убедиться, что события приходят.
4. Прототип → целевая архитектура по порядку из [PROTOTYPE_REVIEW.md §6](PROTOTYPE_REVIEW.md#6-что-делать-с-этим-кодом-дальше-порядок): вебхук + FastAPI + Caddy + Postgres в compose; state machine и SLA; убрать `UKClient` и демо-таймер; роль диспетчера.
5. Домен: `Ticket`, state machine, SLA-калькулятор с тестами; справочник норм — начать проверку по первоисточникам.
6. ML: синтетический датасет (`ml/dataset/`, train 1119 / test 350, обе метки) и обучение (`ml/training/train.py`) готовы; на test — категория accuracy 0.94, аварийность accuracy/recall 0.966, ниже порога уверенности 0.6 — 1.7% и 0.3% жалоб. Модели и `metrics.json` закоммичены в `ml/models/` — после `docker compose up` классификатор работает без обучения на сервере. Дальше: вычистить 5 почти-дублей train↔test; реальная доля аварий в датасете 50% в каждой категории (искусственно) — подобрать порог аварийности на правдоподобном распределении; для LLM (`ai.py`) адаптер ещё предстоит написать.
7. Frontend: Vite + React + TS, проверить `@maxhub/max-ui` и MAX Bridge на веб-версии MAX; авторизация по `initData`.
8. Кастдев: составить гайд, найти 5–8 респондентов.
