# «Домовой» — заявки ЖКХ с нормативным сроком в MAX

Трек «Умный город», хакатон MAX 2026, команда 446.

Житель пишет о проблеме в домовой чат или боту, «Домовой» оформляет заявку в управляющую организацию (УО): называет **нормативный срок со ссылкой на пункт закона** и ответственного. Соседи присоединяются кнопкой «👍 Я тоже», а не плодят дубли. Диспетчер УО видит очередь по 50 домам, отсортированную по сроку. Если срок сорван, житель одной кнопкой получает готовую жалобу в жилищную инспекцию (PDF).

> **Тестовые данные.** Все дома, УО и заявки синтетические и помечены «(демо)». Заявки никуда не передаются. Бот сообщает об этом в каждой карточке.

## Сценарий проверки (7–10 минут)

Все роли проверяются одним аккаунтом MAX: в демо-режиме можно стать диспетчером кнопкой.

### 1. Житель в личке

1. Откройте бота и нажмите «Начать». Выберите один из демо-домов (или перейдите по ссылке `https://max.ru/t446_hakaton_max_bot?start=h_psk001`).
   *Ожидается:* меню с кнопками «Сообщить о проблеме», «Мои заявки», «Пульс дома», «Кто отвечает».
2. Напишите своими словами: «Лифт не работает, застрял между 3 и 4 этажом».
   *Ожидается:* бот определяет категорию и спрашивает, авария ли это, если не уверен. Затем показывает черновик: кто отвечает и срок с основанием (например, «Правила № 170, прил. 2»).
3. «✅ Отправить».
   *Ожидается:* номер заявки, статус и срок; заявка появляется в «Мои заявки».

### 2. Диспетчер УО

4. Главное меню → «🧑‍💼 Демо: войти как диспетчер УО» → «🗂 Очередь заявок УО».
   *Ожидается:* заявки 50 домов, сверху те, у которых срок ближе; 🚨 — просроченные, 👥 — сколько соседей затронуто.
5. Откройте свою заявку → «👀 Принять» → напишите комментарий («мастер придёт завтра к 10:00») → затем «🏁 Выполнено».
   *Ожидается:* через 1–3 секунды в чате приходят уведомления жителю. Последнее спрашивает «Проблема устранена?» с кнопками «Да» / «Нет, не починили».

### 3. Просрочка и жалоба

6. Создайте ещё одну заявку → «Мои заявки» → откройте её → «⏩ Демо: срок истёк».
   *Ожидается:* сдвиг срока записан в историю как демо-действие. Через пару секунд приходит «Нормативный срок истёк» с кнопкой «📄 Жалоба в жилинспекцию». Нажмите её: в чат придёт PDF с фактами и историей заявки.

### 4. Домовой чат (нужна группа, где бот — администратор с правом «Читать все сообщения»)

7. Добавьте бота в группу и выберите дом.
   *Ожидается:* сообщение о привязке с кнопками «Пульс дома», «Листовка с QR», «Кто за что отвечает».
8. Напишите в группу «В подъезде опять не горит свет на 3 этаже».
   *Ожидается:* бот отвечает на сообщение подсказкой со сроком. «📝 Оформить заявку» превращает подсказку в карточку заявки.
9. Со второго аккаунта нажмите «👍 Я тоже».
   *Ожидается:* счётчик соседей растёт. Похожая жалоба от третьего человека получает предложение поддержать, а не новую заявку. Смена статуса диспетчером обновляет карточку в группе.

### 5. Мини-приложение

10. Кнопка запуска в чате с ботом.
    *Ожидается:* «Мои заявки» с таймлайном и сроком, у диспетчера — «Очередь» со счётчиками и фильтрами «просроченные / аварийные».

## Состав и архитектура

```text
MAX ──вебхук HTTPS──▶ Caddy ──▶ bot-контейнер ──▶ PostgreSQL
                                 │  ├─ бот (maxapi): личка и домовые чаты
                                 │  ├─ REST /api/v1 для мини-приложения
                                 │  ├─ мини-приложение (React), отдаётся по /
                                 │  └─ фоновые задачи: доставка уведомлений (outbox), проверка просрочек
                                 └──▶ ml-контейнер: CatBoost — категория и аварийность жалобы
```

- **Бэкенд** — Python 3.13, FastAPI, SQLAlchemy 2 (async) + Alembic. Слои: `domain` (правила заявки, нормативные сроки, ответственность) → `application` (сценарии, по одному на файл) → `infrastructure` (Postgres, MAX, PDF, ML/LLM) → `api` и `bot` (адаптеры). Подробно — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), решения — [docs/DECISIONS.md](docs/DECISIONS.md).
- **Мини-приложение** — Vite + React + TypeScript + MAX UI, [frontend/README.md](frontend/README.md).
- **ML-сервис** — CatBoost на синтетическом датасете, [ml/README.md](ml/README.md). Если сервис недоступен, бот классифицирует по ключевым словам и не падает.
- **Надёжность:**
  - вебхук отвечает 200 сразу, а обрабатывает событие в фоне;
  - повторные доставки MAX отбрасываются (таблица `inbox`);
  - уведомления пишутся в outbox в той же транзакции и доставляются с повторами;
  - состояние диалога хранится в Postgres и переживает перезапуск.

## Запуск одной командой

Нужны Docker и Docker Compose v2.

```bash
cp backend/.env.example backend/.env      # впишите MAX_TOKEN (слайд 1)
docker compose up --build                 # Postgres, бот + API + мини-приложение, ML
```

Что происходит при старте:

- применяются миграции;
- загружаются демо-данные (1 УО, 50 домов, 120 заявок) и тестовые учётки API;
- бот запускается в режиме `polling`.

Проверка:

```bash
curl http://localhost:8080/ready   # {"database":"ok"}
```

> **Важно про токен.** У бота один токен. Пока работает боевой вебхук (адрес со слайда 1), MAX не отдаёт события локальному `polling`. Локальный бот стартует и пишет об этом в лог, но сообщений не получит, а боевой бот продолжит работать. Сценарий в MAX проверяйте на боевом боте. Локальный запуск нужен для воспроизводимости, API и тестов. `POLLING_TAKEOVER=true` снимает вебхук боевого бота, поэтому при проверке его не включайте.

Прод с HTTPS (Caddy, Let's Encrypt): в `backend/.env` задать `BOT_MODE=webhook`, `WEBHOOK_URL=https://<домен>/webhooks/max`, `WEBHOOK_SECRET`; затем `DOMAIN=<домен> docker compose --profile prod up -d --build`.

| Переменная | По умолчанию | Назначение |
|---|---|---|

| `BOT_MODE` | `polling` | `polling` локально, `webhook` в проде |

Полный список с комментариями — [`backend/.env.example`](backend/.env.example), ML — [`ml/.env.example`](ml/.env.example).

### Остановка и повторный запуск

```bash
docker compose down        # остановить, данные сохраняются в томе pgdata
docker compose up -d       # запустить снова
docker compose down -v     # остановить и удалить данные (при следующем старте — чистая демо-база)
docker compose exec bot python -m scripts.seed_demo --reset-test-accounts   # сбросить тестовые заявки API
```

## Зависимости и внешние сервисы

- **Версии зафиксированы:**
  - `backend/uv.lock`, `ml/uv.lock` — Python 3.13, `uv`;
  - `frontend/package-lock.json` — Node 24;
  - образы `postgres:17-alpine`, `python:3.13-slim`, `node:24-alpine`, `caddy:2.10-alpine`.
- **MAX Bot API** (`platform-api2.max.ru`): вебхук, сообщения, кнопки, файлы. Сертификат Минцифры поставляется в `maxapi`.
- **LLM по API** (Yandex AI Studio) — по желанию, по умолчанию выключен. Без него работают правила и CatBoost.
- **Внешних систем ЖКХ не вызываем.** ГИС ЖКХ, АДС и инспекции в MVP смоделированы синтетическими данными.

## Данные

- **Демо-набор:**
  - 1 УО «Комфорт (демо)», 50 домов в Пскове с вымышленными номерами, 120 заявок за 60 дней с историей и просрочками;
  - синтетические жители имеют отрицательные id, и бот никогда им не пишет;
  - генерация — `backend/src/infrastructure/seed/`.
- **Тестовые учётки API:** житель `-100`, диспетчер `-200`, посторонний `-300`. Подписанный заголовок: `MAX_TOKEN=... PYTHONPATH=src uv run python -m scripts.sign_init_data --user-id -100` (в `backend/`).
- **Персональные данные:**
  - храним id в MAX, выбранный дом, роль, тексты заявок;
  - телефон, квартиру и ФИО не запрашиваем, в жалобе житель вписывает их сам;
  - `/privacy` в боте объясняет это и удаляет данные по кнопке.
- **Нормативные сроки** хранятся кодом со ссылкой на пункт документа: `backend/src/domain/tickets/sla.py`, таблица — [docs/DATA.md §2](docs/DATA.md).

## Известные ограничения

- **Домовой чат.** Бот видит сообщения группы, только если он администратор с правом «Читать все сообщения». Без этого работают кнопки и `/start` в группе.
- **Распознавание жалоб в чате** намеренно осторожное: нужны уверенная категория и признак проблемы в тексте. Часть жалоб останется без подсказки, их можно оформить в личке.
- **Классификатор** обучен на синтетических жалобах. Точность на живых формулировках не измерена, для сравнения есть `scripts/compare_classifiers.py`.
- **Нормативные сроки и ссылки** в жалобе взяты из открытых источников и сверяются с текстами документов. Жалобу житель подаёт сам: сервис её не отправляет.
- **Производственный календарь** учитывает праздники по ТК РФ, переносы выходных конкретного года — нет.
- **Мини-приложение** открывается только из MAX: вне MAX нет подписанных данных запуска.
- **Фото в заявке** пока не принимаются.
