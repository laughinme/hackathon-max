# Умный город — бот обращений в УК для мессенджера MAX

Чат-бот, который помогает жителю многоквартирного дома дойти от
«что-то сломалось» до зарегистрированного обращения в управляющую
организацию и понятного статуса по нему.

## Назначение

Сегодня житель не понимает, кто отвечает за проблему, как правильно
её сформулировать и что происходит с обращением после отправки.
Бот берёт это на себя: принимает описание проблемы обычными словами,
задаёт только нужные уточнения, формирует текст обращения, отправляет
его в УК и показывает статус.

## Основной пользовательский сценарий

```
/start
  → Главное меню: «Создать обращение» / «Мои обращения»
  → Быстрый сценарий (вода, свет, отопление, дверь, уборка, лифт)
     или свободный текст прямо в чат
  → AI задаёт уточняющий вопрос
  → Черновик обращения (правится сообщением в чат)
  → «Готово» → отправка в УК, номер и статус
  → «Мои обращения» → список → карточка со статусом, текстом и историей
```

Ключевая деталь интерфейса: **вся навигация происходит в одном
сообщении** — экран перерисовывается на месте, чат не засоряется.
За это отвечает [app/screen.py](app/screen.py).

## Архитектура

```
app/
  main.py            точка входа: Bot + Dispatcher + роутеры
  config.py          конфигурация из переменных окружения
  screen.py          навигация «одним сообщением» (edit in place)
  keyboards.py       inline-клавиатуры
  callbacks.py       payload-и кнопок и фильтры к ним
  texts.py           тексты всех экранов
  states.py          FSM-состояния сценария
  categories.py      справочник типовых проблем
  models.py          обращение и его статусы
  storage.py         in-memory репозиторий обращений
  services.py        сборка зависимостей
  notifier.py        уведомления об изменении статуса
  ai/                контракт AI-слоя + заглушка
  integrations/      клиент системы УК
  handlers/          start / create / my_requests / fallback
ml/                  модель уточняющих вопросов и генерации обращения
  schemas.py         строгий JSON-контракт ответа модели
  prompts.py         промпты (общие для обучения и инференса)
  dataset/           формат и генератор обучающей выборки
  training/          конфиг и SFT-дообучение LoRA
  inference/         HTTP-клиент модели и реализация AIService
  evaluation/        метрики качества
scripts/
  simulate_flow.py   оффлайн-прогон сценария без API MAX
```

Подробности ML-части — в [ml/README.md](ml/README.md),
план обучения — в [ml/TRAINING_PLAN.md](ml/TRAINING_PLAN.md).

Библиотека работы с MAX — [maxapi](https://github.com/love-apples/maxapi),
режим получения событий — long polling (входящие порты не нужны).

## Данные и интеграции

| Компонент | Статус | Комментарий |
|---|---|---|
| API мессенджера MAX | реальный | long polling по токену бота |
| AI-классификация и генерация обращения | **заглушка** | `StubAIService` в [app/ai/service.py](app/ai/service.py): детерминированная логика на правилах |
| Собственная дообученная модель | **основа готова, не обучена** | [ml/](ml/): контракт, промпты, выборка, скрипт LoRA-дообучения, клиент и метрики. Включается `LLM_ENABLED=true`, при сбое откатывается на заглушку |
| Система управляющей организации | **модельная (mock)** | [app/integrations/uk_client.py](app/integrations/uk_client.py): при `UK_API_URL` тот же код уходит реальным HTTP POST |
| Изменение статусов заявки | **демо-имитация** | `DEMO_STATUS_SIMULATION`; в бою — вебхуки от УК |
| Хранилище обращений | in-memory | демо-данные сбрасываются при перезапуске |

Модельные интеграции явно помечены и в интерфейсе бота
(«⚠️ Демо-режим»), и здесь.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `MAX_BOT_TOKEN` | да | — | токен бота MAX (выдаёт `@MasterBot`) |
| `LOG_LEVEL` | нет | `INFO` | уровень логирования |
| `UK_API_URL` | нет | пусто | адрес API УК; пусто → mock-режим |
| `UK_API_TOKEN` | нет | пусто | токен API УК |
| `UK_MOCK_MODE` | нет | `true` | принудительный demo-режим интеграции |
| `DEMO_STATUS_SIMULATION` | нет | `true` | имитация смены статусов заявки |
| `DEMO_STATUS_DELAY_SEC` | нет | `25` | шаг имитации статусов, секунды |
| `LLM_ENABLED` | нет | `false` | использовать дообученную модель вместо заглушки |
| `LLM_BASE_URL` | нет | `http://localhost:8000/v1` | OpenAI-совместимый endpoint модели |
| `LLM_MODEL` | нет | `smart-city-jkh` | имя обслуживаемой модели |
| `LLM_API_KEY` | нет | пусто | ключ endpoint'а модели, если нужен |
| `LLM_TIMEOUT_SEC` | нет | `20` | таймаут запроса к модели |
| `LLM_TEMPERATURE` | нет | `0.2` | температура генерации |

Секреты хранятся только в `.env`, который не коммитится.
Шаблон — [.env.example](.env.example).

## Запуск через Docker (одна команда)

```bash
cp .env.example .env      # и вписать MAX_BOT_TOKEN
docker compose up --build
```

Порты не публикуются: бот сам ходит за обновлениями в API MAX.

Остановка и повторный запуск:

```bash
docker compose down       # остановить
docker compose up -d      # запустить снова в фоне
```

## Локальный запуск без Docker

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env       # вписать MAX_BOT_TOKEN
set -a && source .env && set +a
python -m app.main
```

## Проверка сценария

**Без токена и без сети** — оффлайн-прогон всего CJM на фейковом
транспорте, включая проверку, что навигация идёт одним сообщением:

```bash
python -m scripts.simulate_flow
```

**В мессенджере MAX:**

1. Откройте бота и нажмите «Начать» (или отправьте `/start`).
   Ожидается: приветствие и две кнопки — «Создать обращение»,
   «Мои обращения».
2. «Создать обращение» → экран быстрых сценариев.
   Ожидается: сообщение заменилось, новое не пришло.
3. Нажмите «💧 Вода / протечка» → бот задаёт уточняющий вопрос.
4. Ответьте текстом, например: «Течёт труба в подъезде на 5 этаже».
   Ожидается: экран заменился на черновик обращения с кнопкой «Готово».
5. Напишите «Добавь, что вода стекает на 4 этаж».
   Ожидается: текст черновика обновился на том же экране.
6. Нажмите «Готово».
   Ожидается: номер `ОБР-...`, статус «Отправлено в УК», пометка
   демо-режима. Через ~25 секунд придёт уведомление о смене статуса.
7. «Мои обращения» → список кнопок → нажмите на обращение.
   Ожидается: карточка со статусом, текстом и историей статусов.
8. Отдельно проверьте chat-first вход: из главного меню просто
   напишите «В подъезде не закрывается дверь» — бот сам определит
   категорию и начнёт сценарий.

## Обработка ошибок

- сбой внешней системы УК → экран с причиной и кнопкой повтора,
  дубликат обращения при повторе не создаётся;
- невалидный ответ модели → одна попытка починки, затем откат на
  заглушку: сценарий жителя не прерывается;
- непредвиденное исключение в хендлере → экран ошибки с возвратом
  в главное меню (тупиков нет);
- если экранное сообщение нельзя отредактировать (удалено, устарело),
  бот отправляет новое и продолжает работу с ним.

## Известные ограничения

- собственная модель ещё не обучена: написаны контракт, выборка,
  скрипт дообучения и инференс, но веса не получены, и по умолчанию
  бот работает на заглушке (`LLM_ENABLED=false`);
- стартовая обучающая выборка синтетическая — перед финальным
  обучением её нужно разбавить реальными диалогами;
- интеграция с УК модельная, статусы двигаются по демо-сценарию;
- обращения хранятся в памяти процесса и сбрасываются при перезапуске;
- фото и голосовые сообщения пока не обрабатываются;
- mini-app не реализовано: весь основной сценарий проходится в чате.
