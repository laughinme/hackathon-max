# ML-часть: модель уточняющих вопросов и генерации обращения

Модель решает одну задачу: на каждом шаге диалога либо задать
**один** уточняющий вопрос, либо сформировать **текст обращения**
в управляющую организацию.

> **Статус: основа готова, модель НЕ обучена.** Написаны контракт,
> промпты, генератор выборки, скрипт дообучения, клиент инференса и
> метрики. Обучение — отдельный этап, план по дням и гиперпараметры:
> [TRAINING_PLAN.md](TRAINING_PLAN.md).

## Контракт

Модель отвечает одним JSON-объектом ([ml/schemas.py](schemas.py)):

```json
{
  "action": "ask",
  "category": "water",
  "urgency": "высокая",
  "slots": {"problem": "течёт труба", "location": null,
            "started_at": null, "severity": null, "access": null},
  "missing_slots": ["location", "started_at", "severity"],
  "question": "Подскажите, где именно это происходит — подъезд, этаж?",
  "draft": null,
  "explanation": "Ответственный: аварийная служба УК."
}
```

`action="draft"` — вместо `question` заполняется `draft` с текстом
обращения. Ответ валидируется pydantic-схемой: `ask` без вопроса и
`draft` без текста считаются браком.

Диалог заканчивается, когда собраны обязательные слоты категории:
`problem`, `location`, `started_at` (+ `severity` для аварийных
категорий — вода, свет, отопление, лифт).

## Структура

```
ml/
  schemas.py           контракт ответа модели + слоты
  prompts.py           системный промпт и сборка чата (обучение = инференс)
  dataset/
    schema.py          формат обучающего примера (JSONL)
    synthetic.py       генератор bootstrap-диалогов
    build.py           CLI сборки train/val
  training/
    config.py          база, LoRA и гиперпараметры
    train_lora.py      SFT-дообучение (loss только на ответе модели)
  inference/
    client.py          HTTP-клиент OpenAI-совместимого endpoint'а
    service.py         реализация AIService: валидация, починка, откат
  evaluation/
    metrics.py         продуктовые метрики качества
    run_eval.py        прогон валидационной выборки через модель
```

Один и тот же модуль промптов используется при обучении и на
инференсе — модель видит ровно тот формат, на котором училась.

## Базовая модель

`Qwen/Qwen2.5-7B-Instruct`: лицензия Apache-2.0 (важно для правил
хакатона), сильный русский язык, помещается в LoRA-дообучение на
одной GPU 24 ГБ в 4-битном режиме. Переопределяется через
`ML_BASE_MODEL` или `--base-model`.

## Как обучать

```bash
pip install -r ../requirements-ml.txt

# 1. Выборка
python -m ml.dataset.build --count 4000 --out data/dataset

# 2. Дообучение LoRA-адаптера
python -m ml.training.train_lora --epochs 3

# 3. Раздать модель (пример с vLLM)
vllm serve Qwen/Qwen2.5-7B-Instruct \
    --enable-lora --lora-modules smart-city-jkh=data/adapter \
    --served-model-name smart-city-jkh --port 8000

# 4. Приёмка качества
python -m ml.evaluation.run_eval --base-url http://localhost:8000/v1
```

Затем в `.env` бота: `LLM_ENABLED=true`, `LLM_BASE_URL`, `LLM_MODEL`.

## Данные

Стартовая выборка синтетическая: шаблоны формулировок по шести
категориям, случайный набор известных слотов, из-за чего диалоги
получаются разной длины (от одного вопроса до трёх). Генератор
детерминирован по seed.

**Ограничение, которое нужно закрыть до финального обучения:**
синтетика даёт шаблонный язык и не покрывает реальные сообщения
жителей — опечатки, эмоции, несколько проблем в одном сообщении,
сообщения не по теме. Перед обучением выборку нужно разбавить
реальными и вручную проверенными диалогами.

## Метрики

`ml/evaluation/metrics.py` считает по валидационной выборке:

| Метрика | Смысл |
|---|---|
| `json_parsed`, `schema_valid` | доля ответов, пригодных для бота |
| `action_accuracy` | правильно ли выбрано «спросить» vs «оформить» |
| `slot_precision/recall/f1` | качество извлечения фактов из диалога |
| `invented_norms` | доля текстов с выдуманными ссылками на нормы |
| `empty_questions` | вырожденные ответы вида `ask` без вопроса |

`invented_norms` — ключевая метрика безопасности: модель не должна
выдавать за факт нормативные ссылки, которых не было в диалоге.

Длина диалога (сколько вопросов до готового обращения) метриками
выше не измеряется: пошаговая выборка для этого не годится, нужен
роллаут с имитацией ответов жителя. Это следующий шаг после первого
обучения.

## Поведение при сбоях

`LLMAIService` ([inference/service.py](inference/service.py)):

1. невалидный JSON → одна попытка починки с указанием ошибки;
2. повторный брак или недоступность модели → откат на
   `StubAIService`, житель продолжает сценарий и ничего не теряет.

Поведение проверяется оффлайн: `python -m scripts.simulate_flow`,
сценарий 4.
